# Synthetic RL markets with an adversarial minority

This file describes the corrected implementation. A second audit (event-ramp exploit, bbox/Kaiser wiring, reward accounting, curriculum gate, resume determinism) is documented in [docs/FIXES.md](docs/FIXES.md). Earlier architecture notes and saved research drafts describe several features that were not actually connected to training; do not use them as evidence of implemented PPO, SAC, spoofing, or a learned world simulator.

## Problems corrected

- The logger deadlocked on its 100th buffered message: `log()` held a non-reentrant lock and called `flush()`, which acquired the same lock. It now uses a reentrant lock, with a subprocess timeout regression test.
- Ordinary agents used a heuristic with default traits that mostly selected hold. No ordinary policy was trained. Agent objects were also recreated on reset and between episodes.
- The environment used cumulative profit and arbitrary inactivity penalties, the trainer recomputed a different reward, and the adversary reshaped it a third time. Returned step information was empty. All consumers now use the same environment reward.
- Market orders changed portfolios without settling the matching counterparty; limit fills were never posted to portfolios. Resting orders could overspend the same funds. Portfolio marks were stale after prices moved.
- Resting quotes could freeze the historical tape. Zero padding generated artificial enormous returns. Historical augmentation shuffled price levels and compounded noise across episodes.
- The trainer called nonexistent scheduler/evaluation methods, swallowed exceptions, did not consistently advance its episode counter, and often saved no policies. Evaluation trained fresh agents instead of freezing the learned policies.
- Event lifetimes depended on wall-clock seconds. Forecast contests were not activated correctly and evaluated the end of the input tape instead of the forecast's realized future window. The leaderboard accessed a nonexistent field, and robust aggregation had a broadcasting error and used oracle adversary identities.
- Headless training imported the GUI and downloaded data that it then ignored. Supplied stock data now reaches the trainer; no download is required.

## Actual learning algorithm and population

Each ordinary and adversarial agent has an independent masked categorical advantage actor-critic (A2C-style) policy. There are two 64-unit tanh hidden layers, a policy head and a scalar value head. Adam uses learning rate 0.0003, gamma 0.99, GAE lambda 0.95, 32-transition rollouts, entropy coefficient 0.01, value loss coefficient 0.5, and gradient norm clipping at 0.5. Time-limit truncation bootstraps; market collapse/bankruptcy termination does not. This implementation does **not** claim PPO or SAC.

Trader traits initialize in population order in both training and inference: agent 0 retains its type defaults, agent 1 mutates agent 0, agent 2 crosses agents 1 and 0, then the mutate/cross pattern repeats (`agent[i+1] = mutate(agent[i])`, `agent[i+2] = cross(agent[i+1], agent[i])`). The initialization uses a local seeded RNG. `trait_initialization='homogeneous'` retains the type defaults for controls. Checkpoint snapshots preserve each trader's traits.

Inputs include past returns/volatility, current portfolio weights/cash, asset availability and event availability. No future prices or synthetic regime labels are supplied. Actions are hold and market/limit buys/sells for each available asset; invalid actions are masked. Size is bounded by available capital, inventory, a 10% per-decision budget and the agent's per-asset position limit (30% ordinary, 60% adversarial at submission). Price movement can subsequently move weights past those targets. No borrowing or short selling is allowed.

Adversaries have the same trading actions plus a fixed catalogue of up to 32 simulated event interventions. They start each episode with 10 intervention points, spending 5 only after a successful intervention. Roles remain fixed. The cap is floor(20% of the population), so fewer than five agents implies no adversary. This is a stylized shock-intervention threat model; it does not implement exchange-level spoofing/layering or claim that traders can cause real natural disasters.

Models and optimizers survive episode resets. Checkpoints contain weights, optimizer state, preference weights, RNG states, counters and curriculum state. A JSON manifest references a PyTorch payload. Old JSON checkpoints without trainable policies cannot be resumed. Exact resume is tested at completed episode boundaries on the same software stack; an interrupted partial episode restarts that episode with the saved weights. Load only your own trusted checkpoints.

## Reward definition

For every agent, let V be total marked-to-market cash plus inventory and D = 1 - V / peak(V). Define:

```
pnl  = log(V_next / V_previous) / 0.01
ordinary_reward    = 1.0 * pnl - 0.125 * max(dD, 0) / 0.01 + 0.1 * preference_difference
adversarial_reward = w_p * pnl - 0.1 * max(dD, 0) / 0.01 + min(w_d * (disturbance + kaiser_bonus), 0.5)
```

The ordinary weights are the defaults of a neutral risk preference. The adversarial weights are heterogeneous: `w_p = (0.4 + 0.3 r) s_p / Z` and `w_d = (0.2 + 0.2 (1 - r)) s_d / Z`, with risk preference `r` drawn in [0.3, 0.9], style multipliers `(s_p, s_d)` of front-run (1.15, 1.10), liquidity trap (1.10, 1.20), momentum reverse (1.10, 1.05), volatility spike (1.05, 1.10) and `Z = (0.4 + 0.3 r) s_p + 0.7 + (0.2 + 0.2 (1 - r)) s_d`. There is **no** survival bonus: an adversary that does nothing earns exactly zero (this invariant is tested). Logged reward components always sum to the reward paid: the capped damage term is split into `damage` (ordinary disturbance) and `kaiser_damage` (the Kaiser part), and the ordinary drawdown component is logged at the weight actually charged.

`preference_difference` compares a learned pairwise utility score for the realized decision against keeping the previous holdings without trading. The teacher uses the explicitly defined net-return/downside/turnover/concentration utility in `PreferenceReward`; this is **synthetic preference feedback, not an LLM judge or human-labelled RLAIF dataset**. The preference model updates after scoring a transition and is frozen during evaluation. Adversaries receive no ordinary preference term.

`disturbance` is a bounded, per-asset average of the absolute local price intervention attributable to that agent: its pre-repricing net executed flow plus the effect of events it successfully triggered (delivered at the event's onset), normalized by a 1% return unit and capped at 3 units per step. Unrelated market volatility, action entropy, unfilled submissions and expired events earn no disturbance bonus. This is a simulator-defined local disturbance proxy, not a measured causal harm to other traders or a full counterfactual-market evaluation.

Forecast contests train a separate probabilistic GRU forecaster for each trader, scored only after the actual forecast horizon elapses. At each BBOX close, the realized return path updates the trader's GRU, and the forecast reward (configurable with `forecast_reward_weight`) contributes to policy training. Evaluation freezes the trained model weights while continuing to sample probabilistic predictions. Arbitrary hold, sideways-market and collapse bonuses are removed. A cash-only agent with no intervention receives zero; losing trades remain negative. Reward components, portfolio returns, fees, fills, drawdowns and objectives by agent type are logged separately. The sum of opponents' rewards is not a welfare or profitability measure.

## Execution, seeding and evaluation

Trades between the liquidity provider's refreshed quote and an agent's resting limit order execute at the market quote, so a price gap gives the agent price improvement rather than its stale limit price. Evaluation agents carry the trained agents' private traits (`snapshot()` includes them). Training tapes use hashed seeds (`derive_seed`); the held-out evaluation episodes are the same fixed set (seeds 1,000,000+i) for every run, so comparisons are paired; `env.reset(seed)` seeds both the environment and NumPy so a seed reproduces an episode exactly. The adversary has the same position cap as ordinary agents by default. Evaluation results report the per-type standard deviation and per-episode values (`--eval_episodes`).

## Black-box (bbox) contest and the Kaiser

Every `black_box_frequency` steps (default 20) a round opens. Each RLAIF and adversarial trader submits a sampled price path from its own probabilistic GRU forecaster; the model uses the recent return sequence plus that trader's traits, portfolio exposure, market conditions, and recent action mix. Realised prices are recorded for `black_box_duration` steps. At round close, each enabled training agent updates its own forecaster with the realized return path. Accuracy remains `1 - mean relative price error`; a bounded forecast reward additionally combines improvement over a no-change baseline, probabilistic fit, calibration, and within-round rank. The forecast reward is paid at round close and is included in policy training; evaluation keeps both models frozen while still sampling probabilistic predictions. `TrainConf.bbox_enabled=False` disables contest triggers and forecast submissions/updates/rewards in both training and inference, and zeros the policy inputs for contest state, ensemble consensus and Kaiser direction while retaining the policy input shape. Normal runs automatically load the latest compatible trainer checkpoint from `checkpoint_dir`, including the forecasters. Exactly one agent, the **Kaiser**, wins (ties are broken by calibration and then submission order). The winner's identity, last action, wealth, holdings and trend are broadcast and used in three ways: (1) each ordinary agent may, with probability `susceptibility * 0.3`, swap its sampled choice for the Kaiser's direction on the same asset, and the learner is told which choice was executed. Execution noise on price and quantity is off by default (`execution_noise`), because noise added after sampling makes the credited action differ from the executed one; (2) the adversary's event-scoring rule uses the Kaiser's position bias (exposure minus 10%, so a flat Kaiser counts as 'short' in this long-only market) and trend according to its style, as a logit prior over the 32 event slots (`event_choice='prior'`, default): the policy samples the slot itself, so which event is delivered is credited to it; `'heuristic'` restores the legacy arg-max override and `'learned'` removes the prior; (3) the adversary receives a Kaiser-damage bonus (in 1% units, scaled by `kaiser_bonus_scale`=0.3 so it is on par with ordinary disturbance) **only while its own event is in force** and only when the Kaiser lost value that step.

Optional/diagnostic parts: `bbox_villain_points` (default on; `--no_bbox_villain_points` to disable) lets the Kaiser-adversary earn villain points (+1 per win, capped at 20) so contest performance buys intervention budget; with it off the budget is exactly two events per episode. The robust ensemble forecast is scored every round (`bbox.mean_ensemble_accuracy`, `bbox.best_individual_beats_ensemble`) and, while a contest window is open, its five-step forecast return is an input to every policy (`bbox_consensus`), next to the Kaiser's last action direction (`kaiser_direction`). `--no_kaiser_effects` switches off every Kaiser channel (herding, targeting, bonus, and these two inputs) for clean ablations; `scripts/ablation_grid.py` runs full / no-adversary / no-Kaiser / legacy-ramp across seeds. `curriculum_bbox=True` uses each curriculum level's contest period (50, 30, 20, 15) instead of the fixed one.

Per-episode logs now include the contest summary (rounds, winners, switches, margins), triggered events (adversary and natural), the liquidity provider's cash/inventory/wealth, adversary profile (style, risk preference, ...) and villain points.

## Curriculum

The scheduler advances when the ordinary agents' mean episode reward was positive in more than `thresh` (0.5, 0.65, 0.8) of the last five episodes. The earlier gate compared raw, unbounded reward sums with these fractions, so every level was cleared within ten episodes of the first positive stretch.

## Market and data assumptions

The limit order book uses price/time priority and the resting order's price. Market orders are immediate-or-cancel; limit orders reserve capital/inventory and expire after five ticks. Every matched trade updates both counterparties. A clearly modelled external liquidity provider refreshes quotes around the current mark (default spread 0.1%, depth 1,000 shares per side per asset); its cash and inventory ledger and the fee account allow conservation checks. The provider has unlimited credit/inventory capacity. Default agent fee is 0.01% per fill.

A seeded exogenous price tape always advances. The mark is `tape * exp(news + temporary)`. `temporary` is decaying flow impact, `temporary_next = 0.8 * temporary + 0.002 * signed_flow / 1000`, and a trader **pays** the same impact on its own fills as slippage (otherwise it is marked up by the very move its own order causes). `news` carries events and company shocks: `news_next = 0.99 * news + event_shocks`. In the default `jump` event model an event delivers its whole price drift (scaled by `event_magnitude`, 0.35) at onset; its duration only governs how long its volatility multiplier, jump process and liquidity/spread effects stay in force, and overlapping events share one volatility amplification (the largest active multiplier, capped at 3x). The legacy `ramp` model (drift spread evenly over the duration, all of it decaying) is kept behind `event_impact='ramp'` for reproducing old logs; it creates a predictable trend-and-reversal that the policies learn to harvest (see docs/FIXES.md), so do not use it for new experiments. Active events also thin the book and widen the quote through their liquidity and spread multipliers. The liquidity provider has a finite balance sheet: it stops buying (selling) once long (short) `lp_max_inventory` shares (default 5,000), and its cash, inventory and wealth are logged each episode. `scripts/predictability_audit.py` measures what is still predictable (see docs/FIXES.md). Prices are updated before all portfolios and rewards. Event duration/cooldown uses simulation ticks. Other catalogue fields (sector links, correlations, news sentiment, buy/sell pressure) are not active market mechanisms and should not be claimed as experimental features.

Synthetic tapes have symmetric bull/bear drifts, clustered volatility, correlated asset shocks and explicit seeds. Their parameters are illustrative, not calibrated to an exchange. Supplied historical prices require finite positive values and enough rows for a chronological 80/20 train/evaluation split. Each episode needs steps + 1 prices. CSV/Excel files need an explicit price/close column; timestamps, when present, are sorted and duplicates rejected. Multi-asset input files must be row-aligned by the user. No silent replacement of invalid files with synthetic data is performed.

The environment exposes a custom synchronous joint-action API: dict observations/rewards with scalar episode flags. It is not a PettingZoo AEC or single-agent Gym environment. The episode ends on insolvency or a 50% asset-price collapse; the configured time horizon truncates it. A 10% price rise no longer ends it.

## Evaluation and research use

Evaluation copies learned policies, freezes policy/preference updates, uses held-out synthetic seeds or historical windows, and restores the training RNG state afterwards. Curriculum evaluation uses fixed final-level difficulty so changing training levels does not change the evaluation distribution. Cash return is zero. The logged buy-and-hold reference is a **gross, uncosted primary-asset return**, not a like-for-like capital-constrained trading strategy.

`python -m scripts.validate_training` runs three seeds with zero and one adversary. The saved `docs/validation_results.json` records a short engineering validation: 120 episodes, 24,000 market transitions, and 68,773 fills. All runs completed; every policy made 140 updates. Ordinary-agent held-out returns improved in these short runs, but some remained negative or reached cash-like zero returns. Exploratory training rewards stayed negative in the longer validation. This is evidence of functioning learning and stable execution, not proof of profitability, convergence, robustness or statistical significance.

For a paper, run more seeds and longer training, reserve an untouched final test set, compare against cash/random/passive risk-matched traders with the same execution costs, report per-role net returns and maximum drawdown, and vary minority size, event budget, costs and liquidity. Include uncertainty across seeds and paired no-adversary controls. Do not select only positive runs or interpret a rising adversary reward as improved market health.

The headless trainer is the research entry point. The main GUI now reads the same environment ledger and realized prediction windows; experimental population/resource-editing controls are disabled in that live view. Direct execution of the standalone GUI retains a clearly labelled illustrative demo. Auxiliary world-model/temporal-head modules are not the transition dynamics used by the research trainer.

The validation environment used Python 3.14, NumPy 2.4.6, PyTorch 2.13.0, Gymnasium 1.3.0, Polars 1.33.1 and sortedcontainers 2.4.0. The GUI was connected to the live environment and syntax-checked, but not visually tested in this session.
