20. ExplanatoryWorldModel

This is where the code goes beyond ordinary world modeling.

It tries to represent:

state/action
     ↓
causal factors
     ↓
reward

The code creates:

self.causal_graph

as an adjacency matrix.

Conceptually:

Factor 1 ─────► Factor 3
   │
   └──────────► Factor 5

Factor 2 ─────► Factor 4

But there is a very important caveat:

This is not actually learning a meaningful causal graph yet.

The initialization is:

np.random.rand(...)

and the update is basically:

if reward > 0:
    causal_graph += 0.01
else:
    causal_graph -= 0.01

So this is a placeholder heuristic, not a rigorous causal discovery algorithm




24. Where this code is incomplete
This is important if you're evaluating the code as an actual world-model implementation.
Several components are architectural placeholders.

1. Dynamics model

Reasonable basic architecture.

But:

deterministic
no proper probabilistic transition model
uncertainty head isn't trained
no ensemble
no distribution over next states
2. Reward model

Reasonable basic MLP.

3. Delay model

Architecture exists, but training isn't implemented in train_step().

4. Causal model

Mostly heuristic.

5. Belief state

WorldModelState contains:

belief_state

but the actual implementation doesn't meaningfully use it.

6. prediction_horizon

Exists:

prediction_horizon = 5

but isn't really integrated into planning.

7. Training

The training implementation only trains:

DynamicsModel
RewardModel

The code uses MSE:

$$ L_{dyn} = \| \hat{s}_{t+1}-s_{t+1}\|^2 $$

and:

$$ L_{reward} = \|\hat r_t-r_t\|^2 $$

The relevant implementation is in train_step().

So I would classify this as a prototype world-model framework, rather than a complete state-of-the-art world model.


CAUSAL MODEL
5. But there is a major problem
The arguments:
state
action
reward

aren't actually used to calculate the attribution.

Look at the calculation:

attribution = self.factor_importance * abs(reward)

state isn't used.

action isn't used.

Only:

factor_importance
reward magnitude

are used.

Therefore this model cannot currently distinguish:

action A → reward +10

from:

action B → reward +10

provided the reward has the same magnitude.

It would produce essentially the same factor attribution.

So the current implementation is better described as:

fixed factor-weight attribution

rather than actual causal explanation.

6. explanation_confidence is also misleading

It does:

np.max(attribution)

So if:

attribution =
[0.1, 0.2, 0.6, 0.1]

it reports:

confidence = 0.6

But mathematically, that doesn't establish confidence.

It simply means:

The largest assigned attribution weight is 0.6.

A proper confidence estimate would require something like:

posterior uncertainty
bootstrap variance
ensemble disagreement
calibrated probabilities
Bayesian posterior
statistical significance
counterfactual robustness

None of that exists here.

7. The "causal update" is even more simplified

This function:

update_causal_beliefs(
    state,
    action,
    next_state,
    reward
)

is supposed to update the causal graph.

But the actual implementation is:

if reward > 0:
    self.causal_graph += 0.01
else:
    self.causal_graph -= 0.01

with clipping between 0 and 1.

Therefore:

positive reward
      ↓
EVERY graph connection gets stronger

negative reward
      ↓
EVERY graph connection gets weaker

It doesn't inspect:

state
action
next_state

at all.

So this:

F1 ──► F2
F3 ──► F4

doesn't become stronger because evidence specifically supports:

F1 → F2

Instead the entire matrix changes uniformly.

That's not causal discovery.

8. What real causal reasoning would look like

Suppose the environment has:

speed
distance_to_obstacle
steering
collision
reward

A proper causal model might try to learn:

speed ──────────────► collision
distance ───────────► collision
steering ───────────► collision

collision ──────────► reward

Then suppose:

speed = high
distance = low
steering = normal
collision = true
reward = -100

The model could reason:

high speed
    +
low obstacle distance
    ↓
collision
    ↓
negative reward

And more importantly, it could perform a counterfactual:

What would the predicted outcome have been if speed had been lower while keeping other variables fixed?

That's much closer to causal explanation.
